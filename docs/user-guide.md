## 1. Запуск и доступ

### Production (Docker — рекомендуется для дачи/мероприятия)

```powershell
cd C:\Users\Marat\IdeaProjects\HB25
copy .env.example .env
docker compose up --build
```

Или одной командой: `npm start` / двойной клик по `start.bat`.

| Что | Адрес |
|-----|-------|
| Приложение | http://localhost |
| Проверка backend | http://localhost/actuator/health |
| Swagger (API) | http://localhost/swagger-ui.html |

Остановка: `docker compose down` или `npm run stop`.

### Доступ с телефона (локальная сеть)

1. Ноутбук и телефон в **одной Wi‑Fi-сети**.
2. Docker должен быть запущен.
3. Узнай IP ноутбука (PowerShell):

   ```powershell
   Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -like '192.168.*' }
   ```

4. На телефоне открой `http://<IP-ноутбука>` (например `http://192.168.1.138`).
5. Если не открывается — разреши порт 80 в брандмауэре Windows:

   ```powershell
   New-NetFirewallRule -DisplayName "M-OS Docker" -Direction Inbound -LocalPort 80 -Protocol TCP -Action Allow
   ```

> В Docker-режиме фронт и API идут через один nginx, поэтому отдельная настройка CORS для телефона обычно **не нужна**.

### Важно для QR на телефоне

В `.env` задайте IP ноутбука (не `mos.local`):

```env
MOS_QR_BASE_URL=http://192.168.1.143/qr
```

Затем перезапустите Docker и **заново скачайте** QR в админке — старые картинки всё ещё содержат `mos.local`.

`mos.local` на телефоне гостей **не открывается сам**: hosts-файл Windows действует только на ноутбуке. Для мероприятия удобнее IP.

### Development (для разработки)

- База: `docker compose -f docker-compose.dev.yml up -d`
- Backend: `cd backend && mvn spring-boot:run`
- Frontend: `cd frontend && npm run dev` → http://localhost:5173

## 2. Учётные записи

### Демо-пользователи (при включённом demo seed)

Demo seed включается, если в `.env` задано:

```env
SPRING_PROFILES_ACTIVE=prod,dev
MOS_DEMO_SEED_ENABLED=true
```

| Логин | Пароль | Роль | Описание |
|-------|--------|------|----------|
| `marat` | `Kv7nR2xP` | Администратор | Хост |
| `amina` … `katya` | см. сидер | Участник | 18 игроков вечеринки |

Полный список логинов/паролей участников — в `DemoSeedConstants.PARTY_PLAYERS`.

> **Регистрации нет.** Новых игроков создаёт администратор (через базу или будущий функционал). Войти можно только если вы уже добавлены в текущую игровую сессию.

### Когда можно войти

- Должна существовать сессия в статусе **STARTING** или **ACTIVE**.
- Ваш пользователь должен быть **участником** этой сессии.
- Админ перед началом игры нажимает **«Запустить»** на странице `/admin/session` (STARTING → ACTIVE).

## 3. Инструкция для участников

### 3.1. Вход в игру

1. Открой приложение в браузере (на ноутбуке или телефоне).
2. Перейди на страницу **Вход** (`/login`).
3. Введи логин и пароль, выданные организатором.
4. После входа откроется **Главная** (`/`).

Если вход не удаётся — попроси админа проверить, что ты добавлен в сессию и игра запущена.

### 3.2. Навигация

В меню доступны разделы:

| Раздел | Путь | Назначение |
|--------|------|------------|
| **Главная** | `/` | Сводка: сессия, баланс, квесты |
| **Карта** | `/map` | Карта локаций дачи |
| **Инвентарь** | `/inventory` | Собранные предметы |
| **Кошелёк** | `/wallet` | М-коины и история операций |
| **Квесты** | `/quests` | Задания — **здесь можно начать квест** |
| **События** | `/events` | Расписание игровых событий |

В правом верхнем углу — ваш никнейм и кнопка **«Выйти»**.

### 3.3. Как играть — пошагово

```
1. Войти в приложение
      ↓
2. Главная — посмотреть баланс и активные квесты
      ↓
3. Квесты — нажать «Взять квест» на нужном задании
      ↓
4. Исследовать территорию:
   • смотреть карту (/map)
   • находить QR-коды на даче
   • вводить секретные коды (если организатор выдал)
      ↓
5. Следить за прогрессом:
   • Кошелёк — М-коины
   • Инвентарь — предметы
      ↓
6. Реагировать на события (уведомления + раздел «События»)
      ↓
7. Набрать больше M-Coins к аукциону
```

### 3.4. Что можно делать в каждом разделе

#### Главная (`/`)

- Увидеть название и статус игры (STARTING, ACTIVE, PAUSED, FINISHED).
- Быстро проверить баланс М-коинов и активные квесты.
- Перейти в детальные разделы по ссылкам.

#### Карта (`/map`)

- Смотреть карту дачи с точками интереса.
- **Туман войны:** скрытые локации показываются как «? — зона» без названия.
- Клик по маркеру — описание открытой локации.
- Локации **открываются автоматически** при исследовании (QR, события и т.д.) — вручную на карте открыть нельзя.

#### Инвентарь (`/inventory`)

- Просмотр предметов: название, редкость (COMMON → LEGENDARY), описание, картинка.
- Предметы появляются после QR, секретов, обменов, выдачи админом.

#### Кошелёк (`/wallet`)

- Текущий баланс **М-коинов** (внутренняя валюта).
- История: награды, квесты, QR, секреты, обмены, действия админа.

#### Квесты (`/quests`) — основное действие игрока

1. **Доступные** — возьмите квест кнопкой **«Взять квест»**.
2. Сделайте задание в жизни (тост, сюрприз, подарок…).
3. В разделе **В работе** нажмите **«Готово»** (можно коротко написать, что сделали).
4. Награда — M-Coins или предмет. Система не проверяет действие: надеемся на честность.

Есть задания **для всех**, **кому быстрее** (после лимита сдач у других пропадает) и **личные** (видны только назначенному игроку).

#### События (`/events`)

- Объявления, бонусные периоды, открытие локаций, заморозка рейтинга и др.
- Статус: запланировано, идёт, пауза, завершено, отменено.

#### Уведомления (всплывающие)

На всех страницах в углу появляются **live-уведомления** об изменении событий (WebSocket). Это дополнение к разделу «События».

### 3.5. Игровые механики (что происходит «за кадром»)

| Механика | Как работает |
|----------|--------------|
| **QR-коды** | Размещены на территории. Скан даёт М-коины, предмет или открывает локацию. |
| **Промокод** | Персональные коды от организатора (награды, подсказки). |
| **Числа** | Коллекция номеров — нужно собрать полный набор. |
| **Предметы** | Коллекционные, с редкостью; некоторые уникальны. |
| **Обмены** | Между игроками: предметы + М-коины (API есть, UI пока нет). |
| **Очки** | Категории: общие, исследователь, коллекционер, торговец, квесты. |

### 3.6. QR и секреты

**QR-коды**
1. Откройте обычную **камеру телефона** (не сканер в приложении).
2. Наведите на QR и перейдите по ссылке.
3. Если ещё не вошли в M-OS — войдите; награда приходит автоматически.

Страница `/scan` — инструкция и ручной ввод кода на случай проблем со ссылкой.

**Секреты**
- Страница `/secrets` — ввод персонального кода.
- Альтернатива для тестов: Swagger `POST /api/secrets/redeem`.

### 3.7. Чего участник **не может** делать

- Зарегистрироваться самостоятельно.
- Создавать квесты, локации, QR, события.
- Начислять себе коины.
- Управлять сессией (старт/пауза/финиш).
- Голосования в игре **нет**.

## 4. Инструкция для администратора

### 4.1. Вход и доступ к панели

1. Войти как `marat` / `Kv7nR2xP`.
2. В шапке игрового интерфейса нажать **«Админ»** → `/admin`.
3. Откроется панель с боковым меню.

> Если попасть в `/admin` без роли ADMIN — редирект на страницу **403**.

### 4.2. Разделы админ-панели

| Раздел | Путь | Что делает |
|--------|------|------------|
| **Панель** | `/admin` | Обзор: статус сессии, счётчики, топ-10 по M-Coins |
| **Сессия** | `/admin/session` | **Запуск / пауза / завершение игры** |
| **Игроки** | `/admin/players` | Список участников по балансу |
| **Кошелёк** | `/admin/wallet` | Начисление / списание М-коинов |
| **Предметы** | `/admin/items` | Шаблоны предметов + выдача игрокам |
| **Локации** | `/admin/locations` | Точки на карте (создание и редактирование) |
| **QR-коды** | `/admin/qr` | Создание QR с наградами |
| **Промокод** | `/admin/secrets` | Персональные коды для игроков |
| **Числа** | `/admin/numbers` | Коллекционные числа + выдача |
| **Квесты** | `/admin/quests` | Создание и редактирование заданий |
| **События** | `/admin/events` | Создание событий, смена статуса |
| **Аудит** | `/admin/audit` | Журнал всех действий |

### 4.3. Проведение игры — пошаговый сценарий

#### Этап A. Подготовка (до прихода гостей)

1. **Запустить Docker** (`docker compose up --build`).
2. **Войти** как admin.
3. **Проверить демо-данные** (если demo seed включён) или создать контент вручную:

   | Шаг | Раздел | Действие |
   |-----|--------|----------|
   | 1 | Локации | Клик по карте → название точки |
   | 2 | Предметы | Создать шаблоны → выдать стартовые предметы |
   | 3 | QR-коды | Создать коды с наградами → распечатать/повесить на даче |
   | 4 | Секреты | Персональные коды для отдельных игроков |
   | 5 | Числа | Создать набор чисел для коллекции |
   | 6 | Квесты | Социальные задания (всем или личному) |
   | 7 | События | Объявления, бонусные периоды (опционально) |
   | 8 | Кошелёк | Стартовые балансы игрокам (опционально) |

4. **Проверить карту** — открыть `/map` от имени игрока (или в другом браузере).

#### Этап B. Старт игры

1. **Сессия** (`/admin/session`) → кнопка **«Запустить»**.
   - Статус: `STARTING` → `ACTIVE` (или `PAUSED` → `ACTIVE`).
2. Сообщить гостям адрес: `http://<IP-ноутбука>` и логины/пароли.
3. Игроки входят и начинают играть.

#### Этап C. Во время игры

| Задача | Где |
|--------|-----|
| Приостановить игру | **Сессия** → «Пауза» (`ACTIVE` → `PAUSED`) |
| Возобновить | **Сессия** → «Запустить» |
| Выдать бонус коинов | **Кошелёк** → игрок, сумма, «Начислить» |
| Выдать предмет / число | **Предметы** / **Числа** |
| Запустить событие | **События** → создать → сменить статус на RUNNING |
| Посмотреть, кто что делал | **Аудит** |
| Кто лидирует по монетам | **Панель** / **Игроки** / рейтинг гостя |

#### Этап D. Завершение

1. **Сессия** → **«Завершить»** (`ACTIVE`/`PAUSED` → `FINISHED`).
2. Посмотреть рейтинг по M-Coins — кто собрал больше к аукциону.

### 4.4. Подробно: ключевые разделы

#### Сессия (`/admin/session`)

| Кнопка | Переход статуса | Когда использовать |
|--------|-----------------|-------------------|
| **Запустить** | STARTING или PAUSED → ACTIVE | Начало или возобновление игры |
| **Пауза** | ACTIVE → PAUSED | Перерыв, обед, организационная пауза |
| **Завершить** | ACTIVE или PAUSED → FINISHED | Конец мероприятия |

Все действия записываются в **Аудит**.

#### Локации (`/admin/locations`)

- **Создать:** клик по карте → название → «Добавить точку» (координаты берутся с клика).
- **Редактировать:** клик по маркеру или пункту в списке; повторный клик по карте двигает точку.
- **Удалить:** кнопка «Удалить» в форме или в списке (с подтверждением).

#### QR-коды (`/admin/qr`)

При создании QR укажите:

| Поле | Описание |
|------|----------|
| **Код** | Текст в QR (например `QR-COIN`) |
| **Тип награды** | COIN / ITEM / NONE |
| **Политика сканирования** | FIRST_PLAYER — только первый; EVERY_PLAYER — каждый один раз; LIMITED — лимит |
| **JSON награды** | Например `{"amount": 50}` или `{"itemTemplateId": "..."}` |
| **Локация** | Опционально — при скане открывает локацию |

#### Секреты (`/admin/secrets`)

Персональный код для **конкретного игрока**:

- код, название, описание;
- тип награды: COIN, ITEM, NUMBER, QUEST, NONE;
- JSON награды.

Идеально для: стартовых подарков, персональных заданий, подсказок имениннику.

#### Квесты (`/admin/quests`)

Социальные задания на честном слове:

- название и описание;
- кому: **всем игрокам** или **конкретному** (личное задание);
- правило для общих: **каждый гость один раз** или **лимит N** (кто быстрее);
- награда: монеты / предмет / нет;
- кнопка **«Закрыть незавершённые»** перед аукционом.

#### События (`/admin/events`)

- **Создать:** тип, название, описание.
- **Статус:** SCHEDULED → RUNNING → COMPLETED (или PAUSED, CANCELLED).

Типы: объявление, бонусный период, открытие локации, заморозка рейтинга, аукцион, особое.

Игроки получают **push-уведомления** при смене статуса.

#### Аудит (`/admin/audit`)

Журнал действий: кто, когда, что сделал (сессия, коины, квесты, обмены и т.д.). Фильтры по пользователю и типу действия.

### 4.5. Ограничения админ-панели (важно знать)

- **Нельзя** создавать пользователей через UI — только через БД или seed.
- **Нельзя** удалять квесты и QR через UI.
- Списки **Предметы, QR, Секреты, Числа** в браузере — только созданные в текущей сессии вкладки (после перезагрузки страницы список может быть пуст, данные в БД остаются).
- Админ работает только с **одной текущей сессией** (ACTIVE или STARTING).
- Все admin API: `/api/admin/**` — требуют JWT с ролью ADMIN.

## 6. Частые проблемы

### Backend падает: `password authentication failed for user "mos"`

PostgreSQL запомнил **старый пароль** в volume. Решение:

```powershell
docker compose down -v
docker compose up --build
```

После `-v` база создаётся заново. Не меняйте `POSTGRES_PASSWORD` в `.env` без пересоздания volume.

### Не путать dev и production compose

- **Полный стек:** `docker compose up` + файл `.env`
- **Только БД для разработки:** `docker compose -f docker-compose.dev.yml up`

У них **разные volumes** (`mos_pgdata` и `mos_pgdata_dev`), но раньше могли конфликтовать — сейчас разделены.

### Не могу войти участником

- Проверьте `MOS_DEMO_SEED_ENABLED=true` и профиль `dev` в `.env`.
- Без seed есть только **marat**.

### Вход: «нет активной сессии» / «не участник»

- Админ должен **запустить сессию** (STARTING → ACTIVE).
- Пользователь должен быть в `session_participants` (demo seed добавляет автоматически).

### С телефона не открывается

- Одна Wi‑Fi-сеть с ноутбуком.
- IP ноутбука, не `localhost`.
- Брандмауэр Windows — порт 80.
- Docker запущен (`docker compose ps`).

### Как сканировать QR на телефоне

Не используйте сканер внутри браузера приложения. Рабочий способ:

1. Откройте **обычную камеру** телефона.
2. Наведите на QR до появления ссылки.
3. Перейдите по ссылке — награда придёт автоматически (нужно быть залогиненным).

На странице `/scan` в приложении есть только инструкция и запасной ручной ввод кода.

### CORS-ошибки (только в dev-режиме)

Если frontend на `:5173`, а API на `:8080` — в `.env` backend:

```env
MOS_CORS_ALLOWED_ORIGINS=http://localhost:5173
```

В Docker через nginx CORS обычно не мешает.
